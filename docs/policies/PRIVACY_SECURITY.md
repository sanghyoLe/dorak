> 실행 우선순위 안내: 개인정보 원칙은 그대로 적용한다. AWS·RDS·OpenSearch·Redis에 한정된 통제는 현재 Vercel·Neon·R2의 동등 통제로 해석하며, 실제 개인정보·증빙·결제 수집 전 [비용 우선 배포 문서](../operations/DEPLOYMENT_ENVIRONMENTS.md)의 보안 gate를 먼저 통과한다.

## 1. 목적

이 문서는 도락이 처리하는 개인정보와 민감한 운영 데이터를 식별하고, 수집 최소화, 목적 제한, 보존과 파기, 사용자 권리, 접근 통제, 암호화, 위협 대응, 사고 대응 원칙을 정의한다.

도락은 일반적인 리뷰 서비스보다 다음 고위험 데이터를 처리할 가능성이 있다.

- 현재 위치와 방문 인증 위치
- 영수증 이미지와 결제 흔적
- 예약자 연락처와 동행 인원
- 점주 사업 증빙
- 사용자 리뷰와 사진
- 계정·기기·네트워크의 조작 방지 신호
- 자동화된 리뷰 적격성 및 평점 영향력 판단

이 데이터를 기능 편의를 이유로 하나의 사용자 프로필에 모으지 않고 목적별 경계와 보존기간을 적용한다.

## 2. 개인정보 원칙

### PS-P01. 목적이 먼저다

수집 화면이나 데이터 필드를 만들기 전에 처리 목적, 필수 여부, 보존기간, 접근 역할, 삭제 방법을 정의한다.

### PS-P02. 원본보다 파생 결과를 유지한다

영수증과 정밀 위치 같은 원본은 검증에 필요한 기간만 보관하고 `방문 인증됨`과 같은 최소 파생 결과를 유지한다.

### PS-P03. 공개와 내부를 분리한다

공개 리뷰어 프로필과 로그인 이메일, 예약 전화번호, 점주 서류를 서로 다른 데이터 영역과 권한으로 관리한다.

### PS-P04. 선택권 없는 동의를 강요하지 않는다

서비스 핵심 제공에 불필요한 위치, 마케팅, 개인화, 연락처 접근을 필수 동의로 묶지 않는다.

### PS-P05. 권한은 역할과 목적에 따른다

개발자 또는 운영자라는 이유만으로 모든 사용자 데이터를 볼 수 없다. 민감정보 열람에는 업무 역할, 대상 범위, 사유, 감사 로그를 요구한다.

### PS-P06. 삭제는 전체 생명주기다

주 데이터베이스 삭제뿐 아니라 검색, 캐시, 객체 저장소, 분석 데이터, 백업 만료까지 추적한다.

### PS-P07. 보안 신호도 개인정보로 다룬다

기기, IP, 계정 관계, 위험 점수는 직접 이름이 없어도 개인과 연결될 수 있으므로 접근과 보존을 제한한다.

### PS-P08. 자동화된 판단을 통제한다

리뷰 격리, 영향력 제한, 계정 위험도처럼 사용자에게 중대한 영향을 줄 수 있는 자동화 결과에 사람 검토와 설명·이의 제기 절차를 둔다.

## 5. 처리 근거와 동의 설계

실제 법적 처리 근거는 출시 시점의 기능과 계약 구조에 따라 법무 검토 후 확정한다. 제품과 데이터 모델은 다음 유형을 구분해 기록할 수 있어야 한다.

- 서비스 계약의 체결 및 이행에 필요한 처리
- 법령상 의무 이행을 위한 처리
- 사용자 동의에 기반한 선택 처리
- 별도 동의가 필요한 민감정보 또는 제3자 제공
- 정당한 이익 등 적용 가능성이 있는 별도 근거

개인정보 처리방침에서는 동의를 받아 수집하는 항목과 동의 없이 처리하는 항목 및 법적 근거를 구분해 설명한다.

### 5.1 동의 기록

각 결정은 다음 정보를 가진다.

- 사용자 ID
- 동의 유형
- 문서 버전
- 동의 또는 철회
- 시각
- 채널과 화면 버전
- 법정대리인 확인, 필요한 경우

현재 상태만 덮어쓰지 않고 이력을 보존한다.

### 5.2 선택 동의

별도 선택으로 관리할 후보:

- 현재 위치 기반 주변 검색
- 위치 기반 방문 인증
- 마케팅 푸시·이메일·문자
- 고급 개인화 추천
- 외부 계정 연락처 연동
- 선택적 분석 또는 광고 추적

선택 동의를 거부해도 검색, 음식점 상세, 일반 리뷰 같은 핵심 기능을 사용할 수 있어야 한다.

## 6. 위치정보 설계

### 6.1 기능별 분리

#### 주변 검색

- 사용 시점의 현재 위치를 클라이언트 또는 API 요청에서 사용한다.
- 기본적으로 지속적인 위치 이력을 저장하지 않는다.
- 검색 분석에는 정밀 좌표 대신 격자 또는 행정구역으로 낮춘 값을 사용할 수 있다.
- 권한 거부 시 지역 직접 선택을 제공한다.

#### 방문 인증

- 명시적인 사용자 행동으로 시작한다.
- 지점과의 거리, 시각, 정확도 등 파생 결과를 만든다.
- 원 정밀 좌표는 인증 처리 완료 후 짧은 이의 기간을 제외하고 파기한다.
- 백그라운드 지속 추적을 사용하지 않는다.

#### 길 찾기

- 외부 지도 앱으로 전달되는 좌표와 사용자 위치의 처리 주체를 설명한다.
- 도락이 불필요하게 전체 이동 경로를 수집하지 않는다.

### 6.2 위치기반서비스 검토

출시 전 다음을 법률 검토한다.

- 위치기반서비스사업 신고 대상 여부
- 개인위치정보 이용약관
- 수집·이용·제공 동의 방식
- 위치정보 이용·제공사실 확인자료의 기록 범위와 보존
- 처리 목적 달성 후 파기
- 사용자의 일시 중지, 철회, 열람 요구 수단
- 소상공인 또는 1인 기업 특례 적용 여부와 신고 시점

### 6.3 위치 정확도 최소화

기능에 필요한 정확도보다 정밀한 값을 요구하지 않는다.

- 주변 검색: 수십~수백 미터 오차 허용 가능
- 지점 방문 인증: 지점 환경과 GPS 정확도 고려
- 운영 분석: 행정동 또는 격자
- 공개 콘텐츠: 사용자의 정확한 현재 위치 비공개

## 7. 보존과 파기

### 7.1 보존 정책 원칙

- 법정 보존과 제품 편의를 구분한다.
- `무기한`을 기본값으로 사용하지 않는다.
- 보존 만료시각을 데이터에 기록하거나 정책 엔진으로 계산한다.
- 법적 보존 명령이 있는 데이터는 일반 파기 작업에서 제외한다.
- 파기 작업 성공과 실패를 감사 가능하게 기록한다.

### 7.2 초기 보존기간 후보

아래 기간은 제품 설계 후보이며 법무 검토 후 확정한다.

| 데이터           | 초기 후보                                 | 비고                     |
| ---------------- | ----------------------------------------- | ------------------------ |
| 계정 직접 식별자 | 계정 유지 기간 + 종료 처리 기간           | 법정 보존 분리           |
| 공개 리뷰        | 게시 유지 또는 사용자 삭제까지            | 분쟁·법적 보존 예외      |
| 리뷰 수정 이력   | 리뷰 유지 기간 중 제한 보관               | 공개하지 않음            |
| 리뷰 초안        | 마지막 수정 후 90일                       | 사용자 연장 가능 검토    |
| 영수증 원본      | 인증 완료 후 30일, 분쟁 시 최대 90일 후보 | 파생 결과는 별도         |
| 정밀 위치 원본   | 처리 직후 또는 최대 24시간 후보           | 이의 처리 필요성 검토    |
| 인증 파생값      | 리뷰·점수 재현 필요 기간                  | 원본과 분리              |
| 보안 세션 로그   | 90~180일 후보                             | 위험 사건은 별도 보존    |
| 리뷰 조작 특성   | 목적 달성에 필요한 제한 기간              | 재식별 위험 검토         |
| 고객지원 기록    | 해결 후 3년 후보                          | 거래 분쟁 법정 기준 검토 |
| 운영 감사 로그   | 3년 이상 후보                             | 고위험 작업 별도         |
| 비공개 점주 서류 | 권한 승인 후 단기 보관 후보               | 파생 승인 결과 유지      |

전자상거래가 적용되는 거래 기록은 표시·광고 6개월, 계약·청약철회 및 대금결제·공급 기록 5년, 소비자 불만·분쟁처리 기록 3년 등 현행 시행령 기준을 반영해 별도 보관한다.

### 7.3 파기 방법

- 데이터베이스: 레코드 삭제 또는 키 폐기 기반 암호학적 삭제
- 객체 저장소: 객체 버전과 복제본 포함 생명주기 삭제
- 검색: 삭제 이벤트와 정기 대조
- Redis: 키 삭제 및 TTL
- 분석: 사용자 매핑 제거 또는 재식별 불가능한 집계로 변환
- 백업: 직접 행 삭제가 불가능한 경우 백업 만료, 복구 시 삭제 재적용

### 7.4 파기 검증

정기적으로 샘플 사용자와 객체를 선택해 다음을 확인한다.

- 주 DB 삭제
- 검색 결과 제거
- 공개 CDN 접근 차단
- 비공개 원본 제거
- 분석 사용자 키 제거
- 백업 복원 runbook의 삭제 재적용 가능성

## 8. 정보주체 권리

도락은 사용자가 다음을 수행할 수 있는 셀프서비스와 지원 절차를 제공한다.

- 개인정보 처리 내역 확인
- 공개 프로필과 계정정보 수정
- 리뷰, 사진, 리스트 다운로드
- 개인정보 열람 요청
- 오류 정정 요청
- 처리 정지 또는 동의 철회
- 마케팅 수신 거부
- 위치 이용 동의 철회 및 일시 중지
- 계정 삭제
- 자동화된 결정에 대한 설명 또는 사람 검토 요청이 적용되는 경우 그 절차

### 8.1 신원 확인

권리 요청 처리 전에 요청자가 해당 계정의 본인 또는 적법한 대리인인지 위험에 비례해 확인한다. 과도한 신분증 수집을 기본 방식으로 사용하지 않는다.

### 8.2 데이터 내보내기

내보내기 파일은 다음을 포함할 수 있다.

- 계정 기본정보
- 리뷰와 수정 가능한 콘텐츠
- 사진 목록
- 저장과 리스트
- 방문 및 인증 상태
- 예약 내역, 법적·타인 권리 범위 내
- 동의 이력

내부 조작 탐지 규칙, 다른 사용자의 정보, 법적 비공개 정보는 제외할 수 있다.

### 8.3 계정 삭제

삭제 화면은 다음을 구분해 설명한다.

- 즉시 로그아웃 및 로그인 수단 해제
- 공개 콘텐츠의 삭제 또는 비식별화 선택
- 법정 거래기록의 분리 보관
- 백업 만료까지의 처리
- 진행 중 예약과 분쟁의 처리

## 9. 자동화된 판단과 평점

### 9.1 대상

- 방문 인증 자동 판정
- 리뷰 점수 적격성
- 조작 위험 격리
- 사용자 전문성
- 공개 음식점 점수
- 계정 위험 기반 추가 인증

### 9.2 통제

- 모델 버전과 입력 기준 시각 기록
- 사용자에게 중대한 상태의 상위 사유 안내
- 자동 격리 후 사람 검토 경로
- 오류 정정과 이의 제기
- 모델 변경 영향 평가
- 민감한 특성의 직접 또는 대리 변수 사용 검토
- 광고 계약 데이터를 평점 모델에서 기술적으로 격리

### 9.3 설명 범위

다음은 설명할 수 있다.

- 방문 인증이 확인되지 않음
- 이해관계 공개로 전체 점수에서 제외
- 중복 방문 리뷰로 영향력 제한
- 조작 위험 검토 중
- 최소 표본 미달로 음식점 점수 미표시

다음은 상세 공개하지 않는다.

- 기기 관계망
- 정확한 위험 임계치
- 리뷰별 가중치
- 다른 사용자의 비공개 정보

## 10. 제3자 제공과 처리위탁

### 10.1 공급자 목록 관리

공급자별로 다음을 기록한다.

- 법인명과 서비스
- 처리 목적
- 데이터 항목
- 처리 지역과 국외 이전 여부
- 하위 처리자
- 보존·삭제 조건
- 보안 인증 및 사고 통지 조건
- 계약 종료 시 반환·삭제

### 10.2 주요 공급자 범주

- 클라우드 인프라
- 소셜 로그인
- 결제대행
- 지도·지오코딩
- 문자·알림톡·이메일
- 푸시 알림
- 오류 추적과 분석
- 이미지 안전 검사
- 자동 번역
- 고객지원 도구

### 10.3 데이터 최소화

오류 추적 공급자에게 리뷰 원문을 보내거나 번역 공급자에게 사용자 식별자를 함께 보내지 않는다. 결제대행사에는 거래에 필요한 정보만 전달한다.

### 10.4 국외 이전

공급자의 저장·지원 위치를 확인하고 국외 이전이 발생하면 법적 근거, 국가, 시기와 방법, 항목, 목적, 보유기간, 거부 방법을 정책에 반영한다.

## 11. 암호화와 키 관리

### 11.1 전송

- 외부 및 내부 통신에 TLS 사용
- 인증서 자동 갱신과 만료 경보
- 외부 웹훅 서명 검증
- 관리자 접근에 강한 인증

### 11.2 저장

- RDS, S3, OpenSearch, Redis 지원 범위의 저장 암호화
- Restricted 버킷과 데이터베이스 필드는 별도 KMS 키 검토
- 애플리케이션 필드 암호화가 필요한 이메일, 전화번호, 인허가 번호 정의
- 검색이 필요한 식별자는 원문 대신 keyed hash 또는 별도 토큰 사용

### 11.3 키 관리

- 코드와 환경 파일에 키 저장 금지
- Secrets Manager 및 KMS 사용
- 환경별 키 분리
- 키 사용 권한 최소화
- 회전 및 비상 폐기 runbook
- 백업과 복구 시 키 가용성 검증

## 12. 인증 보안

- 소셜 OAuth/OIDC의 state, nonce, PKCE 검증
- 계정 연결 전 기존 세션 재인증
- 이메일·전화번호 변경 시 기존 채널 통지
- refresh token 회전과 재사용 탐지
- 기기별 세션 관리와 전체 로그아웃
- 점주·운영자 MFA
- 비밀번호를 지원할 경우 강한 해시와 유출 비밀번호 방어
- 계정 복구 과정의 사회공학 공격 대응
- 로그인·복구 rate limit

계정 존재 여부를 로그인·복구 오류 메시지로 과도하게 노출하지 않는다.

### 13.3 고객지원 마스킹

### 13.4 점수와 광고 격리

- 광고 서비스 계정은 `rating` schema 쓰기 권한이 없다.
- 평점 게시 작업은 승인된 모델 결과만 활성화한다.
- 점수 수동 변경은 일반 운영 기능으로 제공하지 않는다.
- 긴급 수정은 2인 승인과 감사 로그를 요구한다.

- 영수증 OCR 전체 결과
- 정밀 위치
- 점주 서류
- 결제 토큰과 카드정보
- 리뷰 초안과 비공개 증빙

### 16.2 허용되는 참조

- 내부 사용자 ID
- 요청·추적 ID

- 리소스 ID
- 비식별 처리된 지역
- 처리 시간과 결과 상태

내부 ID도 결합 시 개인을 추적할 수 있으므로 로그 접근과 보존을 제한한다.

### 16.3 Redaction

중앙 로거와 관측성 SDK에 필드명 및 패턴 기반 redaction을 적용한다. 단위 테스트와 운영 샘플 검사로 redaction이 실제 작동하는지 확인한다.

## 17. 분석과 데이터 활용

### 17.1 이벤트 최소화

분석 이벤트는 질문과 지표에 필요한 필드만 수집한다. 전체 검색어, 리뷰 원문, 정밀 좌표를 편의상 웨어하우스에 복제하지 않는다.

### 17.2 사용자 키

- 운영 사용자 ID와 분석 사용자 키를 분리할 수 있게 한다.
- 광고용 식별자와 서비스 계정 ID를 기본 결합하지 않는다.
- 익명 방문과 로그인 후 방문의 병합은 고지된 범위에서 수행한다.

### 17.3 집계와 가명처리

- 점주 분석은 개인별 방문 기록보다 최소 집계 기준을 사용한다.
- 작은 집단의 성별·연령·지역 조합을 제공하지 않는다.
- 외부 데이터 제공에는 재식별 위험 평가와 계약을 요구한다.
- 가명정보와 익명정보를 혼동하지 않는다.

### 17.4 AI 학습

사용자 리뷰, 사진, 비공개 증빙을 생성형 AI 모델 학습에 사용하는 것은 서비스 운영 목적과 별개의 정책으로 다룬다. 외부 모델 학습에 전송하지 않으며, 향후 사용하려면 목적·근거·거부 방법·보존을 별도로 검토한다.

- 공급망 공격자
- 취약점을 악용하는 외부 공격자

### 18.3 주요 위협

| 위협                | 주요 통제                                      |
| ------------------- | ---------------------------------------------- |

| 영수증 탈취         | 비공개 업로드, 짧은 보존, 접근 감사            |

| 관리자 남용         | 직무 분리, 사유 입력, 2인 승인, 감사           |

## 20. 사고 대응

### 20.1 단계

1. 탐지 및 신고 접수
2. 사건 지휘자 지정
3. 영향 범위와 데이터 등급 확인
4. 접근 차단과 증거 보존
5. 근본 원인 제거
6. 법정 통지 및 사용자 안내 판단
7. 안전한 복구
8. 사후 분석과 통제 개선

### 20.2 준비물

- 비상 연락망
- 공급자 사고 연락처
- 토큰·키 긴급 회전 절차
- 계정 일괄 세션 철회
- 공개 버킷 차단
- 점수·검색 롤백
- 예약·결제 연속성 절차
- 규제기관 및 사용자 통지 템플릿

### 20.3 증거 보호

사고 대응 로그는 접근자를 제한하고 무결성을 유지한다. 조사 편의를 이유로 관련 없는 사용자 데이터를 대량 복제하지 않는다.

## 21. 연속성과 복구

- RDS 시점 복구
- S3 버전 및 생명주기 정책
- 인프라 코드로 환경 재구성
- 검색 전체 재색인
- Redis 손실 시 핵심 서비스 복구
- 암호화 키 복구 절차
- 정기 복구 훈련
- 예약·결제 공급자 장애 시 reconciliation

복구 목표는 서비스별 BIA 후 확정한다. 평점 갱신 지연보다 예약 거래와 개인정보 통제가 우선한다.

## 22. 미성년자

- 서비스 가입 가능 연령과 법정대리인 동의 요건을 출시 전에 확정한다.
- 미성년자의 정밀 위치와 방문 패턴 공개를 제한한다.
- 아동 사진의 공개 및 신고를 보수적으로 처리한다.
- 주류 업종과 콘텐츠의 연령 제한을 적용한다.
- 연령 확인을 위해 불필요한 주민등록번호를 수집하지 않는다.

## 23. 개인정보 영향평가형 검토

법정 의무 여부와 별개로 다음 기능에는 내부 영향평가를 수행한다.

- 정밀 위치 방문 인증
- 결제 내역 기반 방문 인증
- 계정·기기 관계망 기반 조작 탐지

- 점주 대상 사용자 집계 분석
- 외부 데이터 결합
- 생성형 AI 처리
- 국외 공급자 도입

평가 항목:

- 목적과 필요성
- 대체 수단
- 데이터 흐름
- 처리 근거
- 사용자 기대와 고지
- 오용·유출 피해
- 보존기간
- 접근 권한
- 자동화 오류와 구제
- 잔여 위험 승인
