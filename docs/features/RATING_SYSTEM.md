## 1. 목적

이 문서는 도락의 공개 음식점 점수, 리뷰어 전문성, 리뷰 적격성, 랭킹, 점수 업데이트, 조작 방지, 설명 정책을 정의한다.

평점 시스템의 목적은 사용자가 남긴 별점을 예쁘게 평균 내는 것이 아니다. 서로 다른 평가 습관과 데이터 양, 방문 신뢰도, 음식 장르 경험을 고려해 특정 음식점에서 만족할 가능성을 비교 가능한 신호로 제공하는 것이다.

## 2. 시스템 목표

### RS-G01. 예측 유용성

공개 점수가 높은 음식점일수록 독립적인 이후 방문자가 만족할 가능성이 높아야 한다.

### RS-G02. 조작 저항성

점주, 대행사, 리뷰 농장, 보상형 캠페인이 적은 비용으로 점수를 의미 있게 움직이기 어려워야 한다.

### RS-G03. 신규·소규모 음식점의 공정성

리뷰가 적다는 이유만으로 나쁜 음식점으로 단정하지 않되, 적은 표본으로 상위 랭킹에 오르지 않게 한다.

### RS-G04. 취향 차이 존중

다수와 다른 평가를 했다는 사실만으로 리뷰어의 영향력을 낮추지 않는다. 전문성과 신뢰도를 합의도와 혼동하지 않는다.

### RS-G05. 광고 독립

광고, 점주 구독, 예약 계약, 매출 기여도는 공개 점수와 랭킹 입력값에서 제외한다.

### RS-G06. 재현과 감사

어떤 모델 버전과 어떤 입력 데이터로 점수가 산출되었는지 재현할 수 있어야 한다.

### RS-G07. 제한적 설명 가능성

사용자에게 점수의 의미와 주요 원칙을 설명하고 자신의 리뷰 포함 상태를 안내하되, 조작에 악용될 세부 탐지 규칙은 공개하지 않는다.

## 3. 비목표

- 음식의 절대적 우열을 객관적으로 증명하지 않는다.
- 모든 사람에게 동일한 맛집 순서를 제공하지 않는다.
- 유명세, 매출, SNS 언급량을 품질과 동일시하지 않는다.
- 리뷰 텍스트의 감성분석만으로 사용자의 입력 별점을 바꾸지 않는다.
- 음식점의 위생 또는 안전을 사용자 평점만으로 판정하지 않는다.
- 점수 하나로 가격, 서비스, 분위기, 접근성의 모든 차이를 숨기지 않는다.

## 4. 용어

| 용어 | 정의 |
| --- | --- |
| 원점수 | 사용자가 직접 입력한 종합 평가 |
| 조정점수 | 리뷰어의 평가 습관 등을 보정한 리뷰 단위 값 |
| 리뷰 가중치 | 방문 인증, 전문성, 최신성, 무결성 등을 결합한 영향력 |
| 적격 리뷰 | 공개 음식점 점수 계산에 포함될 수 있는 리뷰 |
| 유효 표본수 | 가중치 쏠림을 고려한 실질 리뷰 수 |
| 사전분포 | 리뷰가 적을 때 사용하는 장르·지역 기반 기본 기대치 |
| 사후점수 | 사전분포와 적격 리뷰를 결합한 내부 품질 추정치 |
| 공개 점수 | 사용자에게 표시되는 보정 및 캘리브레이션된 점수 |
| 전문성 | 특정 장르 또는 지역에서 리뷰어가 쌓은 검증된 경험 수준 |
| 무결성 | 리뷰와 계정이 조작 또는 이해관계로부터 독립적일 가능성 |
| 모델 버전 | 계산 공식, 파라미터, 입력 규칙의 배포 단위 |

## 5. 평가 입력

### 5.1 종합 평가 척도

- 사용자는 1.0부터 5.0까지 0.5 단위로 종합 평가를 입력한다.
- UI는 각 점수의 언어적 의미를 함께 제시한다.
- 3.0을 무조건 긍정 또는 부정으로 정의하지 않고 "기대에 부합한 보통의 경험"에 가깝게 안내한다.
- 종합 평가는 공개 음식점 점수의 핵심 사용자 입력이다.

권장 라벨은 다음과 같다.

| 점수 | 사용자 안내 의미 |
| --- | --- |
| 1.0 | 매우 불만족 |
| 1.5 | 불만족 |
| 2.0 | 아쉬움이 큼 |
| 2.5 | 다소 아쉬움 |
| 3.0 | 무난함 |
| 3.5 | 만족 |
| 4.0 | 매우 만족 |
| 4.5 | 특별히 훌륭함 |
| 5.0 | 드물게 뛰어난 경험 |

### 5.2 세부 평가

음식, 서비스, 분위기, 가격 만족도 및 장르별 세부 차원을 수집할 수 있다. 초기 공개 종합 점수는 종합 평가를 중심으로 계산한다. 세부 평가를 임의 가중합해 종합 점수를 만들지 않는다.

세부 평가는 다음 용도로 사용한다.

- 음식점 특성 설명
- 개인화 추천
- 리뷰 품질 및 완결성 신호
- 장르별 분석
- 점주용 집계 피드백

세부 평가가 공개 점수 공식에 포함될 경우 별도 모델 버전 변경과 사전 검증을 요구한다.

### 5.3 재방문 의사

재방문 의사는 종합 평가와 별도 신호로 저장한다. 초기 모델에서는 점수 입력값으로 직접 합산하지 않고 캘리브레이션과 예측 성능 평가에 사용한다.

### 5.4 텍스트와 사진

리뷰 길이 또는 사진 수가 많다는 이유만으로 높은 가중치를 자동 부여하지 않는다. 구체적인 주문 메뉴, 방문 맥락, 실제 경험 정보는 리뷰 완결성 신호가 될 수 있지만 긍정적 표현 여부는 영향력 조건이 아니다.

## 6. 리뷰 적격성

### 6.1 적격성 상태

리뷰는 다음 상태 중 하나를 가진다.

- `pending`: 게시되었으나 점수 포함 판정 전
- `eligible`: 점수 계산에 포함 가능
- `ineligible`: 알려진 사유로 점수 계산에서 제외
- `quarantined`: 조작 또는 분쟁 검토 중으로 일시 제외

리뷰의 공개 상태와 적격성 상태는 독립적이다. 공개 가능한 협찬 리뷰라도 전체 공개 점수에서는 제외될 수 있다.

### 6.2 기본 적격 조건

다음 조건을 모두 만족해야 한다.

- 게시 상태가 점수 계산을 허용한다.
- 유효한 사용자와 지점에 연결된다.
- 원점수가 허용 범위에 있다.
- 방문일이 미래가 아니다.
- 동일 방문의 중복 리뷰가 아니다.
- 삭제, 법적 차단, 중대한 정책 위반 상태가 아니다.
- 점주·직원 등 직접 이해관계가 점수 포함을 금지하지 않는다.
- 조작 위험이 격리 기준보다 낮다.

### 6.3 이해관계별 기본 처리

| 이해관계 | 공개 가능 여부 | 전체 점수 기본 처리 |
| --- | --- | --- |
| 전액 자비 방문 | 가능 | 포함 가능 |
| 일반 공개 할인·쿠폰 | 가능 | 포함 가능, 필요 시 낮은 보정 |
| 초대·무료 제공 | 명시 후 가능 | 제외 |
| 원고료·광고비 수령 | 명시 후 가능 | 제외 |
| 직원·점주·직계 관계 | 명시 후 제한적 가능 | 제외 |
| 관계 미공개 후 적발 | 정책에 따라 제한 | 제외 및 무결성 검토 |

예약 서비스 이용이나 도락의 일반 사용자 리워드 자체는 긍정 평가를 조건으로 하지 않는 한 이해관계로 보지 않는다.

### 6.4 반복 방문

동일 사용자가 같은 지점을 여러 번 평가할 수 있다. 다만 한 명이 지점 점수를 지배하지 않도록 사용자·지점 조합의 누적 영향력에 상한을 둔다.

권장 처리:

- 가장 최근 적격 리뷰에 기본 영향력을 부여한다.
- 이전 리뷰는 경험 변화 신호로 유지하되 감쇠한다.
- 동일 사용자의 전체 합산 가중치는 일반 리뷰 한 건의 일정 배수를 넘지 않는다.
- 음식점의 소유권이나 콘셉트가 실질적으로 변경되면 운영 검토 후 별도 정체성으로 분리한다.

## 7. 방문 인증 점수

방문 인증은 실제 방문 가능성을 높이는 신호이지, 리뷰 내용의 진실성이나 음식 취향의 우월성을 보장하지 않는다.

### 7.1 인증 등급

| 등급 | 예시 | 의미 |
| --- | --- | --- |
| V0 | 인증 없음 | 방문 주장만 존재 |
| V1 | 위치 또는 촬영 메타데이터 | 약한 보조 신호 |
| V2 | 영수증, 매장 QR | 지점·시점 연관성이 높은 신호 |
| V3 | 예약 완료 + 착석/완료, 결제 확인 | 거래 기반 강한 신호 |
| VX | 수동 검증 | 운영 검토로 확인된 예외 |

인증 등급별 실제 가중치는 모델 설정으로 관리한다. 인증 없는 리뷰도 즉시 배제하지 않지만, 데이터가 충분한 경우 인증 리뷰보다 낮은 영향력을 가질 수 있다.

### 7.2 복수 인증 결합

복수 인증 수단을 단순 합산하지 않는다. 서로 강하게 연관된 위치와 사진 신호를 독립 증거처럼 중복 계산하지 않도록 인증 수단 간 상관관계를 반영한다.

### 7.3 인증 취소

재사용 영수증, 위조 증빙, 예약 미방문이 확인되면 인증을 취소할 수 있다. 인증 취소는 리뷰 삭제와 별개이며 다음 점수 계산에 반영한다.

## 8. 리뷰어 평가 습관 보정

### 8.1 문제 정의

어떤 사용자는 만족한 식당에도 평균 3.0을 주고, 다른 사용자는 비슷한 경험에 평균 4.5를 줄 수 있다. 두 원점수를 동일 기준으로 평균하면 음식점보다 리뷰어의 습관이 점수를 좌우한다.

### 8.2 계층적 기준선

사용자 `u`, 장르 `c`의 평가 기준선은 다음 요소를 결합한다.

- 전체 사용자 평균
- 해당 장르 평균
- 사용자의 전체 평가 평균
- 사용자의 해당 장르 평가 평균
- 각 평균의 표본 수와 분산

표본이 적은 사용자의 기준선은 전체 및 장르 평균에 강하게 수축하고, 충분한 이력이 쌓이면 개인 기준을 더 반영한다.

개념식:

```text
reviewer_baseline(u, c)
  = shrink(
      global_category_mean(c),
      reviewer_category_mean(u, c),
      eligible_review_count(u, c)
    )
```

### 8.3 조정 리뷰값

```text
adjusted_rating(u, i, c)
  = category_reference(c)
    + raw_rating(u, i)
    - reviewer_baseline(u, c)
```

실제 모델에서는 극단값을 제한하고, 사용자별 분산이 매우 작은 경우의 과도한 확대를 막는다.

### 8.4 합의도를 전문성으로 사용하지 않는다

리뷰어가 다수 평점과 자주 일치한다는 이유만으로 전문성을 높이지 않는다. 그렇지 않으면 초기 다수 의견이 자기 강화되고 숨은 명점이나 정당한 비판이 억제된다.

다만 다음 항목은 별도로 감시한다.

- 무작위 입력에 가까운 패턴
- 모든 식당에 동일한 점수만 반복
- 서로 연결된 계정 집단의 조직적 극단 평가
- 방문 맥락과 양립하기 어려운 대량 리뷰 속도

## 9. 리뷰어 전문성

전문성은 인기도나 유명세가 아니라 검증된 식경험의 깊이와 범위를 의미한다.

### 9.1 전문성 입력

- 해당 장르의 적격 방문 수
- 서로 다른 음식점 수
- 시간에 걸친 활동 지속성
- 방문 인증 비율
- 하위 장르의 다양성
- 특정 지점 또는 그룹에 대한 과도한 집중 여부
- 정책 위반 및 이해관계 이력
- 구체적인 주문 및 방문 정보의 완결성

팔로워 수, 좋아요 수, 광고 성과, 직업적 유명세는 점수 영향력에 직접 포함하지 않는다.

### 9.2 경험량 포화

리뷰 수가 많을수록 전문성은 증가할 수 있지만 선형으로 증가하지 않는다.

```text
experience_component = log(1 + eligible_distinct_visits)
```

수백 건을 작성한 사용자가 수십 건을 작성한 사용자보다 수십 배 영향력을 갖지 않도록 포화 함수를 사용한다.

### 9.3 다양성

한 음식점만 반복 방문한 깊은 경험과 여러 음식점을 비교한 넓은 경험을 구분한다. 음식점 공개 점수 영향력에는 비교 가능한 서로 다른 지점 경험을 더 중요하게 보고, 개인화 추천에는 반복 방문 취향도 활용할 수 있다.

### 9.4 전문성 공개

내부 연속값을 그대로 공개하지 않는다. 최소 데이터 기준을 충족한 경우 다음처럼 설명 가능한 공개 등급을 사용할 수 있다.

- 탐색 중
- 경험이 쌓인 리뷰어
- 장르 전문 리뷰어
- 지역·장르 전문 리뷰어

등급 명칭은 권위 인증처럼 오해되지 않도록 사용자 조사 후 확정한다.

## 10. 리뷰 가중치

리뷰 `r`의 최종 가중치는 여러 독립 성분의 곱과 상한으로 구성한다.

```text
weight(r) = cap(
  base_weight
  × verification_factor(r)
  × expertise_factor(user, category)
  × recency_factor(r)
  × integrity_factor(r)
  × disclosure_factor(r)
  × repeat_visit_factor(r)
)
```

### 10.1 가중치 설계 규칙

- 어느 하나의 긍정 신호만으로 영향력이 폭증하지 않게 한다.
- 무결성 위험은 강한 감점 또는 격리를 적용할 수 있다.
- 전문성 최대 사용자와 신규 사용자 사이의 격차에 상한을 둔다.
- 인증 리뷰가 일반 리뷰를 완전히 무효화하지 않게 한다.
- 이해관계가 확인되면 다른 긍정 신호와 무관하게 전체 점수에서 제외할 수 있다.

### 10.2 최신성

음식점 품질은 셰프, 소유권, 메뉴, 가격, 운영 방식에 따라 변한다. 기본 최신성은 완만한 지수 감쇠를 사용한다.

개념식:

```text
recency_factor(age_days) = floor + (1 - floor) × 2 ^ (-age_days / half_life_days)
```

초기 후보값:

- 기본 반감기: 540일
- 최소 바닥 가중치: 0.20
- 중대한 콘셉트 변경: 별도 분리 또는 변경점 모델 적용

장르별 방문 주기와 음식점 변화 속도를 검증한 후 반감기를 조정한다.

## 11. 음식점 품질 추정

### 11.1 단순 평균을 사용하지 않는 이유

- 적은 표본의 극단값이 랭킹을 지배한다.
- 리뷰어별 점수 기준이 다르다.
- 조작 계정 수를 늘리는 공격에 취약하다.
- 오래된 평가와 최근 평가를 동일하게 취급한다.
- 한 명의 반복 방문이 과도하게 반영될 수 있다.

### 11.2 기본 베이지안 추정

초기 모델은 장르와 필요 시 지역을 고려한 사전분포에 조정 리뷰값을 결합한다.

```text
posterior_mean(i, c)
  = (
      prior_strength(c) × prior_mean(c)
      + Σ[weight(r) × adjusted_rating(r)]
    )
    / (
      prior_strength(c) + Σ[weight(r)]
    )
```

여기서:

- `i`: 음식점 지점
- `c`: 대표 또는 계산 장르
- `prior_mean`: 장르 기준 기대값
- `prior_strength`: 리뷰가 적을 때의 보수성
- `weight`: 적격 리뷰의 최종 가중치

### 11.3 계층적 모델로의 확장

데이터가 충분해지면 사용자 편향과 음식점 품질을 공동 추정하는 강건한 계층적 모델을 사용한다.

```text
raw_rating(u, i, c, t)
  ~ robust_distribution(
      global_mean
      + category_effect(c)
      + branch_quality(i)
      + reviewer_bias(u, c)
      + time_effect(i, t),
      variance
    )
```

오차 분포는 극단값에 민감한 정규분포만 사용하기보다 Student-t 또는 순서형 로짓 모델을 후보로 검증한다.

### 11.4 유효 표본수

가중치가 소수 리뷰에 몰렸는지 확인하기 위해 Kish 유효 표본수를 사용한다.

```text
effective_sample_size
  = (Σ weight)^2 / Σ(weight^2)
```

공개 점수와 랭킹 자격은 단순 리뷰 수와 함께 유효 표본수를 고려한다.

### 11.5 점수 표시 최소 조건

초기 정책 후보:

- 적격 리뷰 수 3개 미만: `평가 집계 중`
- 유효 표본수 3 미만: `평가 집계 중`
- 적격 리뷰어 수 3명 미만: `평가 집계 중`
- 조작 검토 중 리뷰 비중이 높음: 공개 점수 유지 또는 보류

최소 조건은 전국에 일률 적용하기보다 데이터 성숙도에 따라 조정할 수 있지만, 동일 랭킹 안에서는 일관된 기준을 사용한다.

## 12. 공개 점수

### 12.1 점수 범위

- 공개 점수는 1.00에서 5.00 범위로 표시한다.
- 두 자리 소수는 정밀한 측정값이 아니라 랭킹 안정성과 작은 차이를 표현하기 위한 표시다.
- 점수 옆에 리뷰 수, 인증 비율, 업데이트 날짜를 함께 제공한다.

### 12.2 캘리브레이션

장르별 평가 문화가 다르더라도 공개 점수의 의미가 크게 달라지지 않게 단조 캘리브레이션을 적용할 수 있다.

캘리브레이션 목표:

- 같은 공개 점수에서 이후 방문 만족 확률이 장르별로 유사하다.
- 점수 분포를 인위적으로 특정 비율에 맞추지 않는다.
- 장르별 상위 몇 퍼센트인지는 점수와 별도 정보로 제공한다.
- 모델 변경 시 과도한 점수 점프를 최소화한다.

### 12.3 표시 문구

점수만으로 확정적 우열을 표현하지 않는다.

예시:

- `4.12 · 적격 리뷰 86개 · 방문 인증 72%`
- `평가 집계 중 · 리뷰 2개`
- `최근 평가 변동성이 큼`
- `점수 업데이트 2026-09-03`

### 12.4 원점수 평균

사용자 입력 원점수의 단순 평균을 공개 점수와 같은 위치에 표시하지 않는다. 필요하면 리뷰 분포 화면에서 "사용자 입력 분포"로 제공하고 공개 점수와 명확히 구분한다.

## 13. 랭킹

### 13.1 랭킹 자격

음식점은 다음 조건을 충족해야 공식 랭킹 후보가 된다.

- 공개 점수 최소 조건 충족
- 유효 표본수 및 리뷰어 수 기준 충족
- 현재 영업 중 또는 개업 예정 정책에 부합
- 대표 장르와 지역이 확정됨
- 중대한 조작 또는 데이터 분쟁 검토 상태가 아님
- 해당 랭킹 기간 안의 최소 최신 리뷰 신호 충족

### 13.2 랭킹 점수

단순 공개 점수 내림차순만 사용하면 불확실성이 큰 신규 음식점이 과대평가될 수 있다. 공식 랭킹은 사후분포의 보수적 하한 또는 기대 효용을 사용한다.

개념 후보:

```text
ranking_score = posterior_mean - uncertainty_penalty
```

또는:

```text
ranking_score = P(branch_quality > quality_threshold)
```

사용자 화면에는 복잡한 내부 값을 표시하지 않고 랭킹 기준과 최소 조건을 설명한다.

### 13.3 동점 처리

내부 점수가 사실상 같은 음식점에 임의의 정밀 순위를 부여하지 않는다. 다음 방식을 검토한다.

- 공동 순위
- 점수 구간 그룹
- 동일 구간에서 거리, 예약 가능 여부 등 사용자 선택 정렬

광고 계약이나 매출은 동점 처리 기준으로 사용할 수 없다.

### 13.4 지역 및 장르

- 지점의 실제 위치를 기준으로 지역 랭킹을 만든다.
- 복수 장르 지점은 각 장르 자격 조건을 별도로 충족해야 한다.
- 지나치게 세분된 장르의 리뷰 수가 부족하면 상위 장르로 합친다.
- 전국 랭킹은 지역별 데이터 밀도 차이가 품질 차이처럼 보이지 않는지 검증한다.

### 13.5 어워드

연간 어워드는 특정 기준일의 모델, 입력 스냅샷, 자격 조건을 고정한다. 이후 점수 변동으로 과거 수상 이력을 자동 삭제하지 않는다. 폐업 또는 중대한 부정행위가 확인되면 별도 상태와 설명을 추가한다.

## 14. 개인화 점수

개인화 추천은 전체 공개 점수와 별도다.

```text
personal_match(user, branch)
  = f(
      public_quality,
      taste_similarity,
      followed_reviewers,
      dietary_preferences,
      price_preference,
      distance,
      context
    )
```

### 14.1 표시 원칙

- `도락 점수 4.08`과 `내 취향 일치 91%`를 구분한다.
- 개인화 값이 전체 공개 점수나 공식 랭킹을 변경하지 않는다.
- 사용자가 개인화를 끄더라도 전체 검색과 평점을 이용할 수 있다.
- 민감한 방문 기록을 개인화 설명에서 노출하지 않는다.

## 15. 조작 방지

### 15.1 위험 신호 범주

#### 계정 신호

- 짧은 기간의 대량 계정 생성
- 인증 수단 재사용
- 제재 계정과의 연관성
- 비정상적인 로그인 및 기기 전환

#### 방문 신호

- 동일 영수증 또는 결제 증빙 재사용
- 지리적으로 불가능한 방문 속도
- 영업시간과 맞지 않는 반복 방문
- 예약 취소 또는 노쇼와 충돌하는 방문 주장

#### 리뷰 행동 신호

- 특정 지점에 집중된 신규 계정 활동
- 비정상적으로 동기화된 게시 시각
- 극단 점수만 반복하는 집단
- 동일한 리뷰·사진·메뉴 조합의 재사용

#### 관계망 신호

- 동일 기기, 네트워크, 결제, 초대 코드의 계정 군집
- 점주 계정과 리뷰어 계정 사이의 비정상 연결
- 여러 음식점에 반복되는 대행사형 패턴

#### 콘텐츠 신호

- 복제 또는 경미하게 변형된 문장
- 타인의 사진 재사용
- 음식점과 무관한 홍보 링크
- 생성형 콘텐츠의 대량 자동 게시 패턴

생성형 AI 사용 자체를 금지하지 않는다. 실제 방문 없이 대량 생성하거나 타인의 경험을 가장하는 행위를 문제로 본다.

### 15.2 위험 대응 단계

| 위험 수준 | 처리 |
| --- | --- |
| 낮음 | 정상 처리 및 모니터링 |
| 중간 | 가중치 제한, 추가 인증 요청, 지연 반영 |
| 높음 | 점수 격리, 운영 검수 |
| 확정 위반 | 점수 제외, 콘텐츠 조치, 계정 제재 |

자동 시스템은 점수 격리와 추가 검증을 수행할 수 있다. 장기 계정 정지나 중요한 공개 제재는 정책에 따른 사람의 검토를 기본으로 한다.

### 15.3 공격 비용 증가

- 전화 및 소셜 인증만으로 높은 영향력을 주지 않는다.
- 계정 나이만으로 신뢰를 주지 않는다.
- 리뷰 수를 빠르게 늘리는 것보다 서로 다른 검증 방문을 요구한다.
- 동일 집단의 영향력에 군집 상한을 둘 수 있다.
- 점수 반영을 지연하고 모델 세부 가중치를 비공개로 유지한다.

### 15.4 허위 신고 공격

경쟁 음식점이나 이해관계자가 정상 리뷰를 대량 신고해 숨기지 못하도록 신고 수 자체를 위반 증거로 사용하지 않는다. 신고자 신뢰도, 증빙, 독립적 정책 검토를 분리한다.

## 16. 모델 버전과 배포

### 16.1 상태

- `draft`: 개발 및 오프라인 실험
- `shadow`: 사용자 노출 없이 운영 데이터로 계산
- `active`: 공개 점수 생성
- `retired`: 신규 계산 중단, 과거 재현용 보존

### 16.2 배포 절차

1. 변경 가설과 성공·중단 기준 작성
2. 과거 데이터 재생 평가
3. 어뷰징 시나리오 시뮬레이션
4. 장르·지역·신규·소규모 음식점 영향 분석
5. 섀도 계산 및 기존 모델 비교
6. 제품, 데이터, 운영 승인
7. 제한 공개 또는 단계적 전환
8. 사후 모니터링과 되돌리기 준비

### 16.3 변경 등급

| 등급 | 예시 | 조치 |
| --- | --- | --- |
| Patch | 버그 수정, 동일 의도 구현 | 재계산 및 간단 공지 |
| Minor | 가중치·사전분포 변경 | 섀도 검증, 변경 이력 공개 |
| Major | 모델 구조·척도 의미 변경 | 광범위 검증, 사용자 설명, 병행 비교 |

### 16.4 점수 원자적 게시

전체 재계산 도중 지점마다 서로 다른 모델 버전이 노출되지 않도록 계산 결과를 준비 영역에 저장한 뒤 승인된 배치 단위로 활성화한다.

## 17. 계산 및 공개 주기

### 17.1 초기 운영안

- 리뷰 적격성: 게시 직후 비동기 판정
- 내부 점수: 매일 증분 계산
- 전체 검증 재계산: 주 1회
- 공개 점수 게시: 하루 1회 고정 시각
- 어뷰징 긴급 조치: 필요 시 즉시 적격성 변경 후 점수 재계산 요청

실시간 점수 반영을 제공하지 않는다. 이는 조작자가 공격 효과를 즉시 관찰하기 어렵게 하고 배치 검증 시간을 확보한다.

### 17.2 계산 기준 시각

각 공개 배치는 `input_cutoff_at`을 가진다. 기준 시각 이후 작성·수정·삭제된 리뷰는 다음 배치에 반영한다.

## 18. 사용자 설명과 이의 제기

### 18.1 공개 설명

도락은 다음 원칙을 공개한다.

- 단순 평균이 아님
- 리뷰어별 평가 기준 보정
- 장르 경험과 방문 인증 반영
- 적은 리뷰에 대한 보수적 처리
- 광고와 점수의 독립
- 조작 의심 리뷰의 영향 제한
- 정기적인 점수 업데이트

정확한 가중치, 위험 임계치, 기기·관계망 규칙은 공개하지 않는다.

### 18.2 리뷰어 안내

작성자는 자신의 리뷰에 대해 다음 상태를 확인할 수 있어야 한다.

- 게시 상태
- 방문 인증 상태
- 점수 적격성 상태
- 제외 또는 격리의 상위 사유
- 추가 인증 또는 이의 제기 방법

사용자에게 자신의 정확한 영향력 숫자를 제공하지 않는다. 영향력 게임화를 막고 탐지 규칙 노출을 줄이기 위함이다.

### 18.3 점주 안내

점주는 개별 리뷰의 정확한 점수 기여도나 리뷰어 내부 신뢰도를 확인할 수 없다. 점수 추세, 적격 리뷰 수, 인증 비율, 공개 정책 설명을 제공한다. 점주가 특정 리뷰의 점수 제외를 구매하거나 요구할 수 없다.

## 19. 모델 평가

### 19.1 오프라인 품질 지표

- 이후 독립 방문자의 만족도 예측 정확도
- 재방문 의사 및 저장 후 방문 전환과의 상관
- 시간 분할 검증에서의 안정성
- 장르·지역별 캘리브레이션 오차
- 점수 순위 변동성
- 신규 음식점의 과대·과소평가
- 적은 표본의 극단 점수 발생률

### 19.2 무결성 지표

- 확정 조작 리뷰의 점수 기여 차단율
- 정상 리뷰 오탐 격리율
- 공격 시뮬레이션당 필요한 계정·방문 비용
- 조작 제거 전후 상위 랭킹 변화
- 이의 제기로 적격성 결정이 뒤집힌 비율

### 19.3 공정성 점검

- 수도권과 비수도권의 점수 표시 가능 비율
- 대형점과 소형점의 최소 표본 도달 차이
- 장르별 점수 분포 및 예측 의미
- 신규 개업점의 노출 및 랭킹 진입 시간
- 고가·저가 음식점의 가격대별 캘리브레이션
- 방문 인증 수단을 사용하기 어려운 사용자 집단의 기여 제한 정도

점수 분포가 같아야 공정하다고 가정하지 않는다. 동일 점수의 의미와 오류율이 집단별로 크게 달라지는지를 본다.

## 20. 모니터링과 경보

### 20.1 계산 파이프라인

- 입력 리뷰 수 급감 또는 급증
- 적격성 판정 지연
- 지점별 점수 미생성
- 이전 모델 버전 혼재
- 검색 인덱스와 원장 점수 불일치
- 재계산 시간 및 실패율

### 20.2 분포 변화

- 전체 및 장르별 점수 평균·분산
- 4.0 이상 음식점 비율의 급변
- 신규 계정 리뷰의 기여 비중
- 인증 방법별 리뷰 분포
- 특정 지역 또는 점주 그룹의 급격한 상승
- 전문 리뷰어 소수에게 집중된 총 가중치

### 20.3 긴급 중단 조건

- 점수 계산 오류로 대규모 순위 역전
- 광고·계약 데이터가 점수 입력에 유입
- 개인정보가 점수 설명 또는 로그에 노출
- 한 리뷰 또는 한 계정의 비정상적 영향력
- 삭제·제재 리뷰가 계속 계산에 포함

긴급 중단 시 이전 활성 모델과 점수 스냅샷으로 되돌린다.

## 21. 점수 API 출력 원칙

공개 API는 다음 수준의 정보를 제공할 수 있다.

```json
{
  "score": 4.08,
  "status": "published",
  "eligibleReviewCount": 86,
  "verifiedVisitRatio": 0.72,
  "updatedAt": "2026-09-03T04:00:00+09:00",
  "modelLabel": "dorak-rating-v1",
  "confidenceLabel": "established"
}
```

공개 API에 포함하지 않는 정보:

- 리뷰별 정확한 가중치
- 사용자 내부 전문성 연속값
- 계정 및 기기 위험 점수
- 조작 탐지 임계치
- 비공개 리뷰와 증빙 존재 여부
- 다른 음식점의 비공개 비교 데이터

## 23. 테스트 시나리오

### 정상 시나리오

- 후한 리뷰어와 박한 리뷰어가 같은 음식점을 비슷하게 평가
- 신규 리뷰어가 첫 인증 리뷰 작성
- 전문 리뷰어가 비전문 장르 리뷰 작성
- 오래된 리뷰와 최근 리뷰가 혼재
- 한 사용자가 같은 지점을 여러 번 방문
- 음식점이 이전하거나 장기간 휴업

### 공격 시나리오

- 신규 계정 100개가 한 지점에 5점 부여
- 오래된 정상 계정이 짧은 시간에 여러 지점을 홍보
- 동일 영수증을 여러 계정에서 사용
- 경쟁 음식점에 1점 리뷰 군집 생성
- 협찬 관계를 숨긴 전문 리뷰어
- 점주가 정상 리뷰를 집단 신고
- 사진과 문구만 조금씩 바꾼 자동 리뷰

### 운영 시나리오

- 리뷰 삭제 후 점수 재계산
- 모델 버전 롤백
- 잘못 병합된 지점 분리
- 리뷰 적격성 이의 제기 인용
- 점수 계산 중 일부 작업 실패
- 공개 배치 직전 데이터베이스 장애

## 24. 미결정 사항

- 공개 점수 두 자리 소수 유지 여부
- 원점수 입력을 0.5 단위로 할지 더 단순한 언어형 척도로 할지 여부
- 최소 적격 리뷰·리뷰어·유효 표본수의 실제 값
- 장르와 지역 사전분포의 계층 구조
- 리뷰어 전문성 최대 배율
- 방문 인증 등급별 영향력 범위
- 반복 방문 누적 영향력 상한
- 공개 점수 캘리브레이션 함수
- 공식 랭킹의 불확실성 패널티 방식
- 소유권 및 셰프 변경 시 과거 리뷰 감쇠 정책
- 점수 변동 알림 제공 여부
- 리뷰 적격성 이의 제기 처리 목표 시간
