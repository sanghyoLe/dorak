# Project instructions

## UI and design

- Use the `hallmark` skill for every UI, page, layout, copy, or visual-style change.
- Read the existing tokens, fonts, component ownership, routes, and nearby product docs before editing. Preserve the established product tone and working interaction logic.
- Treat the Hallmark anti-slop rules as hard requirements: no generic AI landing-page structure, decorative section numbers or uppercase kickers by default, inflated editorial hero copy, invented claims, gradients, card-in-card nesting, or decoration without a product reason.
- Prefer short, plain Korean copy grounded in the product and its real data. Do not replace useful product language with abstract positioning copy.
- Keep colours, fonts, spacing, motion, and focus states on the existing token system. Verify responsive UI at 320, 375, 414, and 768px with no horizontal overflow or wrapped clickable labels.
- Run the relevant type, test, build, and visual checks before handing off a UI change. Re-read the Hallmark slop-test gates before calling the work complete.
